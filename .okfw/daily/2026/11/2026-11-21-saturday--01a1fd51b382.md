# 2026-11-21 Saturday

## Phase 0: tooling (ISSUE-001, closed)
- **Changed:** branch `nasa-p10-refactor` from `main` at 0a74e24. Added the ZMakefile, the `p10`, `docs-style` and `wiki` tasks, `.semscope.cue`, `vocabulary.cue`, `clippy.toml`, `rust-toolchain.toml`, the `[lints]` table, this wiki and 20 snapshot tests.
- **Learned:** semscope skips a `#[cfg(test)] mod` block, but not a file that `main.rs` declares under `#[cfg(test)]`. The coverage margin is 0.41%.
- **Next:** Phase 1 (ISSUE-002): split the 41 long functions. Start with the graph logic that the TUI and the export share.

## Phase 1: R4 short functions (ISSUE-002, closed)
- **Changed:** 41 long functions split into helpers and context structs. The shared graph logic is in `src/ui/panels/graph/view.rs`. semscope R4 and the clippy lints `too_many_lines` and `excessive_nesting` are on.
- **Learned:** each agent worktree started from `main`, not from the branch. Check the base of each agent branch before the merge. Parallel builds need `CARGO_INCREMENTAL=0` on this disk.
- **Next:** Phase 2 (ISSUE-003): replace the recursive layout walks with one bounded walker.

## Phase 2: R1 no recursion (ISSUE-003, closed)
- **Changed:** `LayoutWalk` and explicit stacks replace 24 recursive walks. Imports reject layouts deeper than 16 levels or larger than 4096 nodes. NASA-P10-01 is on. ADR-0006 records the design.
- **Learned:** a bound can drop data with no message. Each limit needs an error or a visible notice, and a test. semscope builds the call graph from names, so two functions with one name look like recursion.
- **Next:** Phase 3 (ISSUE-004): bound each loop. The float tick loops can run forever when the step is too small.

## Phase 3: R2 bounded loops (ISSUE-004, closed)
- **Changed:** each production loop has a visible bound. The tick generators are in `ticks.rs`. NASA-P10-02 and `while_float` are on.
- **Learned:** semscope reports `loop` only. Each `while` needed a review by hand. A float loop with `tick += step` is a hang when the step is under half an ulp.
- **Next:** Phase 4 (ISSUE-005): remove `unwrap`, `expect` and discarded results from production code.

## Phase 4: R7 checked results (ISSUE-005, closed)
- **Changed:** no `unwrap`, `expect`, `unreachable` or untyped `let _ =` in production code. `SvgOut` writes the SVG. Dead code is gone, and each `#[allow]` has a reason. NASA-P10-07 and eight clippy lints are on.
- **Learned:** a `[lints]` table applies to the `tests/*.rs` crates too. Each test crate needs its own allow with a reason.
- **Next:** Phase 5 (ISSUE-006): named limits for each input and each growable collection.

## Phase 5: R3 resource limits (ISSUE-006, closed)
- **Changed:** 13 new limits in `src/limits.rs` for files, CLI input, variables, Prometheus results, the search text and the recordings. ADR-0007 has the table.
- **Learned:** a file size check needs two steps: the metadata, then a capped read. A file can grow between the two.
- **Next:** Phase 6 (ISSUE-007): checked conversions in place of `as` casts, and no indexing that can panic.

## Phase 6: R10 casts and indexing (ISSUE-007, closed)

- **Learned:** the work removed four latent panics or wraps: a division by zero, a split UTF-8 char, a negative grid y and a `u16` wrap.
- **Next:** Phase 7 (ISSUE-008): enum dispatch for the annotation providers, no `dyn Fn`, no `macro_rules!`.
